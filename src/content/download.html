Install

Install Ferrite

The script downloads the server and the panel, checks their checksums, and sets up a systemd or OpenRC service. Prefer containers? The image is on GHCR. Every option and the steps after it are in the install guide.

Linux / macOS release install 
curl -fsSL https://raw.githubusercontent.com/koroblabs/ferrite-server/refs/heads/main/install.sh | sudo sh
Docker (ghcr.io) 
docker run -d --name ferrite \
  --restart unless-stopped \
  --network host \
  --cap-add=NET_BIND_SERVICE \
  -v ferrite-data:/var/lib/ferrite \
  ghcr.io/koroblabs/ferrite-server:latest
Build from source 
cargo build --release
sudo cp target/release/ferrite /usr/local/bin/ferrite
Set a web UI password 
ferrite passwd
Default panel shortcut

Ferrite serves a built-in fe.te record that points to the detected local server address, so the panel is easy to find on the LAN.

Container image on GHCR

A small Alpine image is published to ghcr.io/koroblabs/ferrite-server. Mount /var/lib/ferrite so config, data, and updates survive restarts. Run it on the host network so each device keeps its own address; an Unraid Community Apps template is available too.

No root for tunnels

Two WireGuard backends, picked automatically. Kernel mode gives multi-core crypto and line-rate throughput from a CAP_NET_ADMIN capability. Still not root, and it never touches the host routing table. Where that capability or the kernel module is missing, the tunnel runs in userspace (boringtun + smoltcp) with no TUN device and no capability at all. Privileged ports (53/80) just need the usual bind capability.

Runtime-managed updates

The web UI updates through POST /api/update/web, and the server self-updates from GitHub releases once Ferrite is running.
