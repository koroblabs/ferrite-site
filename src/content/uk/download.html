Встановити ferrite

Скрипт завантажує сервер і панель, перевіряє їхні контрольні суми й налаштовує сервіс systemd чи OpenRC. Любите контейнери? Образ є на GHCR. Усі варіанти й наступні кроки описані в інструкції зі встановлення.

Скрипт для Linux / macOS 
curl -fsSL https://raw.githubusercontent.com/koroblabs/ferrite-server/refs/heads/main/install.sh | sudo sh
Docker (ghcr.io) 
docker run -d --name ferrite \
  --restart unless-stopped \
  --network host \
  --cap-add=NET_BIND_SERVICE \
  -v ferrite-data:/var/lib/ferrite \
  ghcr.io/koroblabs/ferrite-server:latest
Збірка з коду 
cargo build --release
sudo cp target/release/ferrite /usr/local/bin/ferrite
Пароль для панелі 
ferrite passwd
Коротка адреса панелі

Ferrite має вбудований запис fe.te з локальною адресою сервера, тож панель легко знайти в мережі.

Образ на GHCR

Невеликий образ на Alpine опубліковано в ghcr.io/koroblabs/ferrite-server. Змонтуйте /var/lib/ferrite для конфігу, даних і оновлень, щоб вони переживали перезапуски. Запускайте в мережі host, щоб кожен пристрій мав власну адресу. Є й шаблон для Unraid Community Apps.

Тунелі без root

Два бекенди WireGuard, вибираються автоматично. Режим ядра дає шифрування на всіх ядрах і повну швидкість лінії, якщо є дозвіл CAP_NET_ADMIN і модуль ядра. Це все одно не root, і таблицю маршрутизації хоста він не чіпає. Де дозволу чи модуля немає, тунель працює в userspace (boringtun + smoltcp) без TUN-пристрою і без жодних дозволів. Для привілейованих портів (53/80) потрібен лише звичайний дозвіл на bind.

Оновлення на ходу

Панель оновлюється через POST /api/update/web, а сервер сам оновлюється з релізів на GitHub, коли Ferrite вже працює.

Сервіси й розклад

Відфільтровані Google, Bing і DuckDuckGo та обмежений режим YouTube, для всієї мережі чи одного профілю.
