Install

One script, then point your network at it

The installer fetches the server and web UI release assets, prepares system paths, and sets up the service for systemd, OpenRC, or launchd. Prefer containers? Pull the image from GHCR.

Linux / macOS release install 
curl -fsSL https://raw.githubusercontent.com/syntlyx/ferrite-server/refs/heads/main/install.sh | sudo sh
Docker — ghcr.io 
docker run -d --name ferrite \
  --restart unless-stopped \
  -p 53:53/tcp -p 53:53/udp \
  -p 80:80/tcp \
  -v ferrite-data:/var/lib/ferrite \
  ghcr.io/syntlyx/ferrite-server:latest
Build from source 
cargo build --release
sudo cp target/release/ferrite /usr/local/bin/ferrite
Set a web UI password 
ferrite passwd
Default panel shortcut

Ferrite serves a built-in fe.te record that points to the detected local server address, so the panel is easy to find on the LAN.

Container image on GHCR

A small Alpine image is published to ghcr.io/syntlyx/ferrite-server. Mount /var/lib/ferrite so config, data, and updates survive restarts — an Unraid Community Apps template is available too.

No root for tunnels

Two WireGuard backends, picked automatically. Kernel mode gives multi-core crypto and line-rate throughput from a CAP_NET_ADMIN capability — still not root, and it never touches the host routing table. Where that capability or the kernel module is missing, the tunnel runs in userspace (boringtun + smoltcp) with no TUN device and no capability at all. Privileged ports (53/80) just need the usual bind capability.

Runtime-managed updates

The web UI updates through POST /api/update/web, and the server self-updates from GitHub releases — once Ferrite is running.

Releases

What's new

Source and tagged releases live on GitHub: ferrite-server and ferrite-web.

v0.2.0 — current

Rules for each device, not just the network. Profiles can block services from a built-in catalog of 43 — TikTok, Roblox, YouTube, Discord and more, one click each — apply on a weekly schedule such as school nights, and force SafeSearch and YouTube Restricted Mode; the same services and SafeSearch work for the whole network, and a tunnel rule can route a whole service. Profiles have a page of their own, and any device or domain opens in a side panel: its profile and whether it applies right now, a day of activity, the services behind it, what it asked for and what was blocked and why — from the query log, the dashboard, the device list or ⌘K. Notifications reach ntfy, Telegram, Discord, Slack or Gotify as readable messages when a tunnel stays down or a device the box has never seen joins. Panel sign-ins now last seven days since last use and survive restarts and updates, and Settings lists every signed-in browser with a way to sign it out. An MCP endpoint, off by default, lets an AI assistant ask why a site is blocked — or, if you allow it, block one. The resolver itself grew too: a blocked name can be answered NXDOMAIN, empty, with 0.0.0.0 or with a block page of your own; an optimistic cache keeps names resolving through an upstream outage; a per-device rate limit and allowed or denied ranges keep it to your network; and manual rules take regular expressions. Coming from Pi-hole or AdGuard Home, Settings reads a Teleporter export or an AdGuardHome.yaml and shows what comes over — lists, rules, records, groups, blocked services — and what can't, before anything changes. And a second ferrite can now follow the first, taking its filtering, records and DNS settings every few minutes, so two resolvers answer alike and you edit in one place. Upgrading: the database moves to schema v12 on first start, so an older ferrite can't open it afterwards — copy ferrite.db first if you may roll back; [proxy] alert_webhook moves to [notifications] by itself; and the panel asks for the password once more.

v0.1.10

A security release for the TLS and QUIC stack under every encrypted upstream. rustls 0.23.46 closes four advisories, among them an unauthenticated ServerHello that could downgrade later connections to classical key exchange, and up to 1 GiB allocated decompressing a certificate before it is verified. quinn-proto 0.11.19 fixes five ways a DoQ peer could crash ferrite or grow its memory without bound, and certificate checks no longer trust the distrusted emSign intermediates. Under the hood blocklists and allowlists now share one implementation instead of two mirrored copies — config, API routes and blocking decisions are unchanged. New in the panel: block or allow a domain in one click from the query log or the dashboard, with an undo; pause filtering for five minutes to an hour — for the whole network or one device — without touching the config; and back up or restore the whole configuration as a single file. Subscription lists now refresh on their own every 12 hours, and a restart after an upgrade no longer holds DNS back while device profiles rebuild. The panel got a pass too: repeated queries fold into one line, tunnel rules and clients read at a glance with a colour per tunnel and an icon per device, every page fits a phone, and the German, Spanish and French translations are proofread.

v0.1.9

A lighter hot path: queries are read and patched on the wire instead of decoded and rebuilt, and on Linux UDP moves in batches — CPU per query drops from ~139 µs to ~19 µs. A blocklist refresh that changed nothing now builds nothing, a profile recompiles only when its own lists move, and the refresh peak on a million-domain list fell from 96 MB to 50 MB. The database now holds only what ferrite observed — everything you configure lives in config.toml — and you choose where it goes: SQLite at a path picked from the box's mounts, or a RAM-only backend, with a size cap and a 30-day default retention. The compiled blocklist can sit in RAM too, sparing an SD card. New switches stop query logging and statistics — including the device inventory — outright.

v0.1.8

WireGuard tunnels can now run on the kernel backend: ferrite builds its own wg interface over netlink and steers only its own traffic through it, so crypto uses every core and throughput follows the link instead of a fixed window. Proxied bytes move with splice(2), never entering user space. Blocking now wins over selective routing, so a blocklisted subdomain stays blocked under a routed domain, and a new client-TTL ceiling keeps devices thin so list, rule and profile changes reach them within a minute. The Linux download is ~20 MB instead of ~171.

v0.1.7

Per-device blocklist profiles with manual block/allow overrides, subscribable allowlists, and a default-deny mode that exempts local names. Egress health gained active latency probes that gate fail-closed routing, down-alert webhooks, Prometheus metrics at /api/metrics, and per-tunnel traffic stats.

v0.1.6

Memory overhaul — the mimalloc allocator, bounded internal caches, and new memory-introspection stats keep long-running RSS low and flat. Tunnel supervision was hardened against stalls and reconnect churn, and the Docker image now exposes 443.

v0.1.5

Transport-independent DNSSEC — signatures now survive over DoT and plain upstreams by raw-forwarding the wire response instead of rebuilding the query. Idle tunnel connections are reaped on a timeout, so memory stays flat under heavy per-device routing.

v0.1.4

Per-device routing rules, upstream-through-tunnel (DNS-over-TCP + DoT), DPI-evasion egress, unified :80 (panel + proxy), DNSSEC request + ECS stripping, diagnostic Tools (nslookup/WHOIS), block-source attribution, and a debug-logging toggle.

Earlier

Selective routing engine, userspace WireGuard / SOCKS5 egress, encrypted upstreams (DoH/DoT/DoQ), compiled blocklists, custom DNS, live stats, and the REST-managed web UI.
